# ニュース知識資産管理システム — プロジェクト概要

**作成日:** 2026-06-28  
**バージョン:** v1.1.0

---

## このシステムは何か

コンサルタントが日々読むニュースを「読んで終わり」にしないための、**個人向け知識資産管理システム**。

ニュースを構造化・蓄積し、業界別・企業別・テーマ別にいつでも検索・活用できる状態を維持する。**AIが秘書として記事登録・分析・DB更新をすべて代行するため、ユーザーは「読む」と「指示する」だけでよい。**

---

## なぜ作ったか（課題感）

| Before（従来） | After（このシステム） |
|---|---|
| ニュースを読んでもすぐ忘れる | 知識として蓄積・検索できる |
| メモが散在してどこにあるかわからない | Notionに一元集約 |
| 業界の全体像を把握するのに時間がかかる | 業界DBを見れば5分でキャッチアップ |
| 企業の過去ニュースを辿れない | 企業DBに示唆・リンク付きで蓄積 |
| コンサルとしての示唆を記録していない | 「示唆」フィールドで自動蓄積 |

---

## システム構成

```
Notion（クラウドDB）
┌─────────────────────────────────────────────┐
│                                             │
│  ニュースDB ─────リレーション────→ 企業DB    │
│  （記事単位で蓄積）      ↘         （企業単位）│
│                           ↘                │
│                            ──→ 業界DB      │
│                                （業界単位）  │
└─────────────────────────────────────────────┘

ローカルファイル（Git管理予定）
schema/ templates/ tests/ logs/ docs/
│
└── Claude（AI秘書）がユーザーの指示を受けて
    3つのDBを連動して自動更新・管理
```

**3つのDBがリレーションで相互接続**されており、ニュース記事から企業・業界への知識ナビゲーションができる。

## 実装機能一覧

### 【A】ニュースDB — 記事管理

| 機能 | 概要 |
|---|---|
| A-1 記事の新規登録（単件） | 記事を「Fact（核心1行）・背景・示唆・業界・タグ・日付」に構造化してNotionに登録 |
| A-2 記事の一括登録（バッチ） | 手書きノート・複数記事を5〜8件単位でまとめて登録。重複確認→整理→登録→レポートの順で実行 |
| A-3 既存記事の補完 | 背景・示唆・タグ・日付が未入力の記事を検索して追記 |
| A-4 業界・タグ付与 | 10業界 × 40タグの固定分類から適切な値をAIが自動提案・付与 |
| A-5 タグ整合性チェック | 全記事のタグが正式定義内か検証。逸脱があれば一覧化して報告 |
| A-6 週次サマリ生成 | 直近1週間の記事から週次ダイジェストを自動生成・保存 |
| A-7 キーワード横断検索・分析 | 複数記事を横断して比較・分析し構造化して提示 |

### 【B】企業DB — 企業情報管理

| 機能 | 概要 |
|---|---|
| B-1 企業情報の自動生成 | ニュース記事に登場する企業を自動検出 → ユーザー確認 → WebリサーチしてNotionに登録 |
| B-2 企業情報フォーマット | ①ビジネスモデル・沿革（300-500字）②社史要約（200字）③基本情報 ④営業利益率推移（5年・1年1行）⑤自分のメモ・学び |
| B-3 ニュース記事のリレーション紐付け | 企業に関連する記事を「関連ニュース記事」フィールドにリンクで接続 |
| B-4 示唆の自動引用 | 関連記事の「示唆」を「自分のメモ・学び」に自動追記（記事タイトル・日付・クリックで飛べるリンク付き） |
| B-5 企業情報の手動追加 | 「〇〇社を追加して」で任意の企業をWebリサーチして登録 |
| B-6 企業情報の更新 | 「〇〇社を最新化して」で最新決算・情報をWebで取得して上書き |
| B-7 既存ニュースからの一括生成 | 「ニュースDBから企業DBを自動生成して」で全記事から主要企業を抽出 → 一括リサーチ → 登録 → リンク付けを実行 |

### 【C】業界DB — 業界情報管理

| 機能 | 概要 |
|---|---|
| C-1 10業界の体系管理 | 自動車・モビリティ / テクノロジー・AI / 半導体・電子部品 / 素材・資源 / 水処理・環境 / エネルギー / 造船・重工業 / ヘルスケア・流通 / メディア・エンタメ / 政策・マクロ経済 |
| C-2 業界詳細ページ（9セクション） | 歴史・変遷 / 市場規模・成長性 / 業界構造・主要プレイヤー / バリューチェーン / 主要トレンド / HOTニュース / 課題・リスク / DX・AI活用動向 / 今後の展望 |
| C-3 HOTニュース自動更新 | ニュースDBに蓄積した記事を業界別に分類してHOTニュースセクションに自動追記 |
| C-4 業界情報のWebリサーチ更新 | 「〇〇業界の情報を最新化して」でWeb取得 → 全セクションを上書き更新 |
| C-5 高市重点分野フラグ | 高市内閣の17重点産業分野への該当タグ（ニュースDB・業界DB両対応） |
| C-6 定量データ管理 | 世界市場規模・CAGR・DX成熟度・最終更新日をプロパティとして管理 |

### 【D】スキーマ・分類体系管理

| 機能 | 概要 |
|---|---|
| D-1 業界タクソノミー | 10業界カテゴリの固定定義。追加・変更はユーザー承認後にtaxonomy.mdとNotion両方を更新 |
| D-2 タグタクソノミー | 40タグの固定定義（テクノロジー系・ビジネス系・産業系・エネルギー系・政策系・企業固有・IP系・高市重点） |
| D-3 スキーマ変更管理 | 変更内容提示 → ユーザー承認 → taxonomy.md更新 → Notion反映 → changelog記録の5ステップ必須フロー |

### 【E】運用基盤（ローカルファイル）

| ファイル | 役割 |
|---|---|
| `schema/taxonomy.md` | 業界・タグの正式定義書（AIが毎セッション参照） |
| `schema/changelog-schema.md` | スキーマ変更履歴 |
| `templates/article-input-template.md` | 記事入力フォーマット |
| `templates/weekly-digest-template.md` | 週次サマリテンプレート |
| `tests/validation_rules.md` | タグ整合性チェックルール |
| `logs/` | セッションログ・週次サマリ保存先 |
| `CHANGELOG.md` | 機能追加・変更履歴 |
| `REQUIREMENTS.md` | 機能要件定義書 |
| `docs/DESIGN.md` | 設計ドキュメント |

## 典型的な使い方

**1. 記事を読んだ後**  
「このニュースをDBに追加して」と伝えるだけ。AIが構造化して登録し、登場企業を自動検出して企業DBへの連携を提案する。

**2. 業界を調べたい時**  
Notionの業界DBを開く。「〇〇業界の情報を最新化して」でAIがWeb検索して全セクションを更新。

**3. 企業を調べたい時**  
企業DBを開く。蓄積したニュースの示唆がリンク付きで一覧表示されている。

**4. 週次レビュー**  
「今週の知識まとめを作って」でAIが週次サマリを自動生成。

**5. 一括整理**  
「ニュースDBから企業・業界DBを自動生成して」で、既存記事全体から3つのDBを一括構築。

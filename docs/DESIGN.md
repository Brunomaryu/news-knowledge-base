## 目的

業界ニュースを**ファクト・背景・示唆**の3層で構造化してNotionに蓄積し、コンサルティング業務での知識活用・提案品質向上を実現する。

---

## アーキテクチャ

```
[入力]                    [処理]               [格納・活用]
手書きノート  ──┐
Web記事      ──┼──▶ Cowork AI ──▶ Notion DB ──▶ 検索・分析
会議・対話   ──┘    (Notion MCP)               週次サマリ
                                               コンサル活用
```

### 設計原則
1. **Notionがマスターデータ**：本リポジトリはルール・設計定義のみ管理
2. **3層構造**：Fact（核心）/ 背景（文脈）/ 示唆（コンサル視点）
3. **検索可能性優先**：業界・タグによる多軸検索を保証
4. **削除しない**：一度登録した記事は原則保持（知識資産）

### フィールド設計

| フィールド | 型 | 必須 | 役割 |
|---|---|---|---|
| Fact | title | ✅ | 記事の核心ファクト（1行・検索のメインキー） |
| 背景 | text | 推奨 | ニュースの背景・前提・文脈 |
| 示唆 | text | 推奨 | コンサルとして読む示唆・論点・So What |
| 業界 | multi-select | 推奨 | 業界カテゴリ（10分類） |
| タグ | multi-select | 推奨 | テーマタグ（39種） |
| 日付 | date | 推奨 | 記事日付（YYYY-MM-DD） |
| Summary | text | 任意 | 要約（旧フィールド、互換性のため保持） |
| 業界／国 | text | 任意 | 旧業界フィールド（参照用、廃止予定） |

### フィールドの優先度
- **Fact + 業界 + タグ**: 最低限必須（検索・分類の基盤）
- **背景 + 示唆**: 知識資産としての本質的価値を担う
- **日付**: トレンド分析に不可欠

## スキーマ設計

詳細は `schema/taxonomy.md` を参照。

### 業界カテゴリ（10分類）の設計思想
製造業コンサルタントの視点から、産業構造に基づく10分類を設計。単純な業種分類ではなく「分析単位として意味のある粒度」を重視。

| カテゴリ | 設計意図 |
|---|---|
| 自動車・モビリティ | EV転換・MaaS・ティア1を一括管理 |
| テクノロジー・AI | 生成AI・クラウド・フィジカルAIを集約 |
| 半導体・電子部品 | 素材から最終製品まで一体で管理 |
| 素材・資源 | 鉄鋼・化学・レアアース等の川上 |
| 水処理・環境 | インフラ×官民連携の独立領域 |
| エネルギー | LNG・再エネ・水素を統合 |
| 造船・重工業 | 防衛需要と民需の交差点 |
| ヘルスケア・流通 | DgS・医療・食品流通の統合 |
| メディア・エンタメ | IP・コンテンツ・ストリーミング |
| 政策・マクロ経済 | 規制・安保・アクティビスト等の横断テーマ |
